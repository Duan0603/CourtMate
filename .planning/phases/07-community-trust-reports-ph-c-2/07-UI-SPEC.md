# Phase 07 — Community Trust & Reports UI Design Contract

> Visual and interaction contract for Phase 07 and the requested coherent redesign of the main mobile shell: Dashboard/Tournaments, Chat, Profile/Settings, shared header, and bottom tab bar. Generated by gsd-ui-researcher; pending gsd-ui-checker verification.

## Scope and Source of Truth

This phase must make trust visible and reporting safe while correcting the current iOS mobile layout defects. The following are locked:

- Brand palette: CourtMate deep navy, vibrant blue, yellow accent, and white (explicit user request; `courtmate-theme.ts`).
- Report reasons: Fake, Spam, Duplicate, and Other with optional details (`07-CONTEXT.md` D-01).
- Five unique reports temporarily hide a tournament pending admin review (`07-CONTEXT.md` D-02). The public UI must not reveal the live report count or threshold progress.
- Verification is assigned manually; there is no “request verification” flow in this phase (`07-CONTEXT.md` D-03).
- Main tabs remain Dashboard/Tournaments, Chat, and Profile; `tracker` remains hidden from the tab bar (existing `_layout.tsx`).
- Real-time messaging remains out of project scope according to `REQUIREMENTS.md`. Existing chat UI may be visually normalized, but Phase 07 must not expand messaging capabilities or promise unsupported delivery/read state behavior.

The screenshots’ overlap/clipping defects are acceptance blockers. No page may depend on guessed `paddingTop` values such as `insets.top + 192`, render multiple search controls for the same function, or place scrollable content behind the fixed header or tab bar.

## Design System

| Property | Value |
|----------|-------|
| Tool | NativeWind 4.0.1 for layout/tokens; Tamagui 1.90 for Sheet, RadioGroup, Input, and portal primitives |
| Preset | `nativewind/preset`; shadcn not applicable to Expo/React Native |
| Component library | Existing CourtMate primitives plus Tamagui; do not introduce a second component system |
| Icon library | `lucide-react-native`; use outline icons at 1.75–2px apparent stroke |
| Font | Geist with system sans fallback; verify the font is loaded before relying on it |
| Platform priority | iOS mobile first at 320–430pt widths; Android equivalent behavior; web is a responsive adaptation |

Implementation contract:

- `courtmate-theme.ts` is the semantic color source of truth. NativeWind and Tamagui aliases must resolve to the same values; remove local `#2563eb`, `#1d4ed8`, slate, orange, and pinkish-background substitutions in redesigned surfaces.
- Prefer NativeWind for static screen layout and shared components. Use Tamagui where its behavior is material (Sheet, RadioGroup, portal, keyboard-aware input). Do not mix NativeWind and Tamagui styling within a single primitive unless required by a third-party API.
- Reuse and restyle `Typography`, `Card`, `VerifiedBadge`, and `ReportModal`; do not create page-local versions.
- Native interaction animation uses React Native `Animated` or Reanimated. Existing GSAP code is web-only and must remain guarded by `Platform.OS === 'web'`; it must not determine native layout.

## Spacing Scale

Declared values, matching the existing NativeWind scale:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, label-to-icon spacing |
| sm | 8px | Compact controls, badge padding, row gaps |
| md | 16px | Screen gutters, card padding, default section gap |
| lg | 24px | Section separation, sheet horizontal padding |
| xl | 32px | Major content breaks |
| 2xl | 48px | Empty-state illustration separation only |
| 3xl | 64px | Reserved page-level breathing room |

Exceptions:

- Every interactive target is at least 44×44pt on iOS, including icon-only buttons, tab items, radio rows, report triggers, chevrons, and close buttons.
- Header height excludes the top safe-area inset and is exactly 60pt in compact form. The Dashboard expanded region is content, not an absolutely positioned header.
- Bottom tab bar visual height is 64pt plus `insets.bottom`; tab content receives bottom padding of `64 + insets.bottom + 16`.
- Form inputs and primary buttons are 48pt high; multiline report details are 104pt minimum.
- Card radius is 16px; compact control radius is 12px; pills and badges use full radius. Avoid arbitrary radii outside 12, 16, 24, and full.

## Typography

Use exactly four sizes and two weights across redesigned screens. Existing 10px, 11px, 12px, 18px, 22px, 24px, and 32px ad-hoc declarations must be mapped to these roles.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Caption / label | 14px | 600 | 20px (1.43) |
| Body | 16px | 400 | 24px (1.5) |
| Section heading | 20px | 600 | 24px (1.2) |
| Page heading | 28px | 600 | 34px (1.21) |

Rules:

- Only weights 400 and 600. Do not use 500, 700, 800, or 900.
- Vietnamese copy must render without clipping at iOS Dynamic Type up to 130%. Important labels wrap to two lines; only secondary metadata may truncate to one line with an accessible full label.
- Buttons and tabs use sentence case, never all caps or increased letter spacing.
- Page titles use 28/34 only when they are in scroll content. Compact fixed headers use 20/24 to preserve vertical space.

## Color

### 60/30/10 distribution

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | White `#FFFFFF` and light canvas `#F7FAFF` | Main canvas, readable content surfaces, forms, message area |
| Secondary (30%) | Deep navy `#00102F`, secondary navy `#061A3D` | Shared header, bottom tab bar, profile hero, strong section bands, primary text |
| Accent (10%) | Vibrant blue `#0077FF` | Primary CTA fills, selected tab indicator, active filter/toggle, focus ring, links |
| Brand highlight | Yellow `#FFC400` | Verified badge, trusted-source emphasis, live/high-value highlight only |
| Destructive | Red `#E8483B` | Report action, validation error, logout/delete confirmation only |
| Success | Green `#22C55E` | Connected/available status and successful completion only |

Accent reserved for: primary CTA fills, active tab icon/label, selected segment/filter chip, input focus border, actionable links, and loading progress. Yellow is reserved for verified-source badges, the CourtMate logo mark, and one exceptional tournament highlight; it is not a generic button color. Red is never used for ordinary navigation.

Contrast contract:

- White text on deep navy; deep navy text on white; white text on vibrant blue; deep navy text on yellow.
- Secondary copy on navy uses `#B8C7E0`; secondary copy on white uses `#52627A`.
- Borders use `rgba(0,16,47,0.12)` on light surfaces and `rgba(255,255,255,0.12)` on navy.
- Verified status is never conveyed by yellow alone: always pair `BadgeCheck` with the text “Nguồn đã xác minh” where space permits and an accessibility label everywhere.

## Shared Mobile Shell

### Safe-area ownership

There is one owner for each inset:

- The root tab layout reads `useSafeAreaInsets()`.
- `AppHeader` applies `paddingTop: insets.top`; tab screens do not repeat top-inset padding while the shared header is visible.
- `CourtMateTabBar` applies `paddingBottom: insets.bottom`; each screen’s scroll content uses the exported tab-bar occupied height rather than a magic number.
- Full-screen subviews (edit profile and an open conversation) may hide shared chrome, but their local header/input bar must then own the relevant top/bottom insets.
- Keyboard-visible chat composer uses `KeyboardAvoidingView` with an offset derived from the local header, not a fixed 90px.

### Shared header

- Compact `AppHeader`: deep navy background, CourtMate logo/wordmark left, optional contextual title, and notification button right; 60pt content height plus safe area.
- Dashboard header remains compact and fixed. Greeting, search, quick actions, category chips, and Dashboard segments live in scroll content beneath it. This eliminates the current absolute expanded header and `insets.top + 192` compensation.
- Chat and Profile use the same compact brand header. On Chat it reads “Trò chuyện”; on Profile it reads “Hồ sơ”.
- Notification badge is yellow with deep-navy numerals. Cap visible count at `9+`; announce the full unread count to assistive technology.
- Header controls must not change height on scroll. A subtle bottom border may appear after the first 8pt of scroll; no native layout collapse animation.

### Bottom tab bar

- Deep navy surface, top border `rgba(255,255,255,0.12)`, exactly three evenly sized destinations: “Giải đấu”, “Trò chuyện”, “Hồ sơ”. Icons alone are not acceptable.
- Each tab target spans one third of the bar and is at least 64pt high. Icon is 22px above a 14/20 label.
- Active: vibrant-blue icon and white label plus a 3px blue indicator; inactive: `#B8C7E0`. Do not use circular light-blue backgrounds.
- Preserve tab state when switching. Tapping the active tab scrolls its root list to top when supported.
- Hide the bar only for edit-profile, schedule detail, tournament detail, report sheet overlay, and open-conversation views. Route identity—not global query-parameter collision—controls visibility.

## Dashboard / Tournaments Contract

### Vertical order

Primary focal point: the search-and-filter row is the first high-contrast actionable element after the greeting and must draw the eye before category chips, segments, or tournament cards. Give the search field the dominant width and the filter button the only yellow count badge in this region; tournament imagery becomes the focal point only after the user scrolls into results.

1. Shared compact header.
2. Greeting row: “Xin chào, {firstName}” and current city control.
3. One search field with Search icon and a separate 44pt filter button. Remove the duplicate search state/control currently split between `_layout.tsx` and `DashboardScreen.tsx`.
4. Horizontally scrollable sport chips.
5. Two-option segment: “Giải đấu” / “Người chơi”.
6. Applied-filter summary and results content.

The greeting/search/category/segment block scrolls normally. Only the shared header and bottom tab bar are fixed. At 320pt width, search occupies remaining row width and the filter button remains 44pt; no label or icon may overlap.

### Search and filters

- Search placeholder: “Tìm giải đấu hoặc nhà tổ chức”. Debounce requests by 300ms; submitting dismisses the keyboard.
- Filter button label for accessibility: “Mở bộ lọc”; show a small yellow count badge when filters are active.
- Open filters as a Tamagui bottom sheet at 85% maximum height with a visible handle, title “Bộ lọc giải đấu”, scrollable groups, and a sticky action row.
- Sport, region, time, fee, level, status, and sort controls use full-row radio/check semantics, not undersized wrapping chips. Selected state uses blue border + check icon.
- Sheet CTAs: secondary “Đặt lại bộ lọc” and primary “Xem {n} giải đấu”. Closing without Apply preserves the previously applied state; draft changes are discarded.
- Applied filters render as dismissible chips below search. Removing a chip updates results immediately.

### Tournament cards and trust

- Card is full-width with 16px radius, 16px padding, 1px navy/12% border, and no more than one low elevation shadow.
- Required hierarchy: image or sport mark; status; title (maximum two lines); organizer row; date/location; fee/slots; primary action.
- `VerifiedBadge` appears immediately after organizer/club name. Compact cards use icon plus accessibility label; detail/profile organizer surfaces show icon + “Nguồn đã xác minh”. Use yellow `BadgeCheck`, never the current blue shield/check variants.
- External Facebook source is a neutral source label, not a verified badge. Do not infer verification from the presence of an external URL.
- Overflow menu is a 44pt `MoreHorizontal` target. It contains “Báo cáo giải đấu” in destructive color; reporting is not the card’s primary CTA.
- Hidden-by-threshold posts are omitted from public lists and search. If a currently open item becomes hidden, replace content with the unavailable state defined below and provide a Back action.

### Dashboard states

- Initial load: 3 skeleton cards with stable heights; header/search remain interactive.
- Pull-to-refresh retains existing results until refresh succeeds.
- Empty heading: “Chưa tìm thấy giải đấu”. Body: “Thử đổi từ khóa, khu vực hoặc bộ lọc để xem thêm kết quả.” CTA: “Đặt lại bộ lọc”.
- Load error: inline full-width state: “Không thể tải giải đấu. Kiểm tra kết nối rồi thử lại.” CTA: “Tải lại giải đấu”. Never show a blank feed.
- Hidden/unavailable detail: “Giải đấu hiện không khả dụng” / “Nội dung đang được xem xét hoặc đã được gỡ.” CTA: “Quay lại danh sách”.

## Report Flow Contract

### Entry and sheet

- Entry points: tournament card overflow and tournament detail overflow. Use Flag icon with “Báo cáo giải đấu”.
- Present `ReportModal` as a modal bottom sheet. On iPhone, maximum open height is `min(content, windowHeight - insets.top - 16)` and the sheet respects keyboard and bottom safe area.
- Header: destructive Flag icon, title “Báo cáo giải đấu”, body “Hãy cho CourtMate biết nội dung nào chưa chính xác. Báo cáo của bạn được giữ riêng tư.”, and 44pt close target.
- Reasons are 48pt minimum radio rows: “Thông tin giả mạo”, “Spam hoặc quảng cáo”, “Nội dung trùng lặp”, “Lý do khác”. No reason is preselected.
- Selecting “Lý do khác” reveals a 104pt multiline field labelled “Mô tả vấn đề”, placeholder “Cho chúng tôi thêm thông tin để kiểm tra…”, maximum 500 characters, with remaining-character count. Details remain optional per D-01.
- Footer has “Đóng báo cáo” secondary and “Gửi báo cáo” destructive. “Đóng báo cáo” closes an untouched sheet immediately; if details were entered, it invokes the discard confirmation below. Submit remains disabled until a reason is selected; while submitting, disable dismissal and show spinner with label “Đang gửi…”.

### Outcomes and safety

- Success closes the sheet and shows a non-blocking confirmation: “Đã gửi báo cáo” / “Cảm ơn bạn đã giúp cộng đồng CourtMate an toàn hơn.” The item remains visible unless the server response says it was hidden.
- Duplicate report error: “Bạn đã báo cáo giải đấu này.” Do not allow repeated submission.
- Generic error: “Chưa thể gửi báo cáo. Kiểm tra kết nối rồi thử lại.” Keep the selected reason and details; CTA “Gửi lại báo cáo”.
- Never display reporter identity, report count, the five-report threshold, or moderation guesses to ordinary users.
- Report is a moderation action, not a destructive confirmation against the user’s own data; the explicit review sheet is sufficient. Cancel discards the unsent form after a confirmation only when non-empty details were entered: “Bỏ báo cáo chưa gửi?” / “Tiếp tục chỉnh sửa” / “Bỏ báo cáo”.

## Chat Contract

This is a visual normalization of the existing surface, not authorization to expand the out-of-scope messaging feature.

### Conversation list

Primary focal point: the most recent unread conversation row draws the eye first through its yellow unread badge, semibold name, and navy-tinted row background. When there are no unread messages, the first conversation row is the focal point; the search field and shared header remain visually subordinate.

- Shared navy header and page heading “Trò chuyện”. Under it, display a search field only when conversations exist.
- Each conversation row is 72pt minimum: 48pt avatar, name, verified badge where applicable, one-line preview, timestamp, and optional unread badge. Avoid floating white cards separated by large gaps; use a single white list with subtle dividers.
- Organizer verification uses the same yellow `VerifiedBadge`. Role text is secondary metadata and must not replace verified status.
- Empty heading: “Chưa có cuộc trò chuyện”. Body: “Khi bạn liên hệ với ban tổ chức, cuộc trò chuyện sẽ xuất hiện ở đây.” CTA: “Khám phá giải đấu”.
- Loading uses stable list skeletons. Error: “Không thể tải cuộc trò chuyện. Kiểm tra kết nối rồi thử lại.” CTA “Tải lại cuộc trò chuyện”.

### Conversation room

- Local navy header owns top inset and includes 44pt Back, avatar, name/verified badge, and connection state. Bottom tab bar is hidden.
- Message area uses light canvas. Own messages are blue with white text; other messages are white with navy text and navy/12% border. Bubble width max 78%; body remains 16/24.
- Do not show “Đã xem” unless backed by a real read receipt. Do not label a socket connection as another person’s online presence.
- Composer is white, owns bottom safe area, and stays above keyboard. Input is 48pt minimum; Send target is 48pt. Disable Send for empty input or failed connection with text-accessible reason.
- Offline banner: “Đang mất kết nối. Tin nhắn chưa thể gửi.” with CTA “Kết nối lại” only if a real reconnection action exists.
- In-app notification banners begin below the safe area/local header, never at hard-coded `top: 20`; they are dismissible, do not obscure Back, and auto-dismiss after 5 seconds.

## Profile / Settings Contract

### Profile root

- Replace the generic “Cài đặt” card list as the first impression with a branded profile hero: deep navy surface, CourtMate logo mark, 80pt avatar, name, username, role, city, and yellow verified badge when applicable.
- Primary hero CTA is “Chỉnh sửa hồ sơ” (blue button). Do not show a verification-request button; manual assignment is locked for MVP.
- Below hero, show a compact stats row only for data that exists (e.g. registered, completed, saved); do not invent ratings or achievements.
- Settings are grouped in white sections with row dividers: “Tài khoản” (profile, security), “Trải nghiệm” (notifications, schedule), and “Quyền riêng tư”. Each row is 56pt minimum with a single 20px icon, label, optional value, and chevron.
- Unsupported settings must be disabled with “Sắp ra mắt”; tapping must not show repetitive alert dialogs that imply the feature exists.
- Logout is a text row at the bottom in destructive red, separated from primary settings. It requires confirmation: “Đăng xuất khỏi CourtMate?” / “Bạn cần đăng nhập lại để tiếp tục.” Buttons “Ở lại” and “Đăng xuất”.

### Edit profile and schedule

- These are full-screen subviews with a local navy header, Back, 20/24 title, and no shared tab bar.
- Edit profile uses one scrollable form, 16px gutters, persistent bottom Save action above the bottom safe area, 48pt inputs, visible labels, and inline validation. Remove duplicate Save buttons.
- Primary CTA: “Lưu hồ sơ”. Success: “Đã lưu hồ sơ.” Error: “Không thể lưu hồ sơ. Kiểm tra thông tin rồi thử lại.”
- Avatar control is 96pt with a visible camera button; do not rely on web-only hover overlays.
- Social-link delete is destructive and uses a 44pt target. If a populated link is removed, confirm “Xóa liên kết này?” with “Giữ lại” / “Xóa”.
- Schedule uses the shared card language and must not include fabricated matches when no API data exists.
- Schedule empty heading: “Chưa có lịch thi đấu”. Body: “Các trận đấu và giải đã đăng ký sẽ xuất hiện tại đây khi có lịch.” CTA: “Khám phá giải đấu”.
- Schedule error heading: “Không thể tải lịch thi đấu”. Body: “Kiểm tra kết nối rồi tải lại lịch của bạn.” CTA: “Tải lại lịch thi đấu”.

## Interaction and Motion

- Press feedback: opacity 0.88 or scale 0.98 for 100–150ms; never both on dense lists.
- Sheets use platform-standard spring/timing; overlay opacity 40%. Respect Reduce Motion by replacing transforms with opacity-only transitions or no motion.
- List content must not animate its height when the header scroll state changes. Filters may animate open/closed only inside the sheet.
- Loading indicators do not cause layout shifts. Skeletons match final card/row geometry.
- Destructive actions provide haptic warning only when platform support exists; haptics are supplementary, not feedback by themselves.

## Accessibility and Responsive Rules

- Target WCAG AA contrast: 4.5:1 for body/caption text, 3:1 for large text and component boundaries.
- Support iOS VoiceOver order matching visual order. Bottom tabs announce label, position, and selected state. Modal sheet traps focus and returns it to the report trigger on close.
- All icon-only controls have explicit Vietnamese labels. Decorative icons are hidden from accessibility.
- Dynamic Type at 130% must not clip header titles, tab labels, filter rows, badges, or CTA labels. Allow wrapping or increase row height.
- At 320pt width, use 16pt gutters and full-width cards; no two-column actions except equal secondary/primary sheet footer buttons. At ≥768pt web/tablet, content max-width is 640px and centered; do not stretch mobile cards edge to edge across desktop.
- Test with iPhone SE width, iPhone 15/15 Pro safe areas, device with home indicator, Android gesture navigation, software keyboard open, and long Vietnamese organizer/tournament names.

## Acceptance Criteria

- On iPhone SE and iPhone 15 Pro, Dashboard search, filter, sport chips, segment, first result, shared header, and tab bar are all separately readable and tappable with zero overlap.

- Chat list and room use the same brand tokens and safe-area rules; unsupported read/online semantics are absent.
